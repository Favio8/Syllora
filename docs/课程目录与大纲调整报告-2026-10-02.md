## 目录示例

```text
主应用目录/
  Syllora.exe
  .syllora/
    <课程 UUID>/
      sources/                  上传或粘贴的原始资料
      <旧资料相对路径>/...        自动迁移的资料
      .syllora/
        course.json             课程与学习记录、任务、当前版本
        creation.json           新建请求参数，防止重复创建
        relocation.json         迁移来源与指纹（迁移课程）
        revisions/...           章节讲义、来源与整理版本
        .staging/...            生成任务暂存及检查点
```

课程显示名称不参与目录拼接，重命名不改变资料路径。模型配置、加密凭据、Host 主密钥与日志继续保存在原 userData；无需重新录入 API Key。未启动真实用户配置，本次验证没有移动个人课程或调用收费模型。

自动迁移不复制扫描排除的隐藏资料、链接、依赖与构建目录，也不复制课程目录中的共享 config.yaml/credentials.json。原文件保持在旧位置，用户确认迁移完成前可用于恢复。非匹配的既有目标拒绝覆盖；暂存迁移副本不作为有效课程打开。

NSIS 清理应用文件前临时将课程目录改名为同级 `<安装目录>.syllora-preserved`，随后恢复原位置。遇到已有备份或目录无法重命名会停止清理；极端中断后，可从该备份恢复课程。安装路径需要可写，不会静默转存到别处。

## 后端接口交接

新建：`POST /api/syllora/createCourse`，请求为 `{payload:{requestId:<UUID>,name,icon?,timezone?}}`，返回 `{ok:true,result:{id,path,created}}`。`id=requestId`，重复请求返回已有课程；同 requestId 不同参数返回 `REQUEST_CONFLICT`。前端使用 `logicalRequest` 保留网络失败后的请求 ID。

旧汇总课程迁移：`migrateCourse` 的新版 UI 仅传 `courseId`，目录由服务端分配；历史 `path` 参数保留兼容。`openCourse(path)` 仅为旧 API 客户端保留，界面不再调用。

初始化：`acceptPartial` 缺省为 `true`，前端也显式传 `true`；兼容客户端显式传 `false` 时仍拒绝部分结果。缺页与失败范围保留在任务/manifest 中，完全无正文仍失败。

新增 Host 选项 `managedCoursesRoot` / 环境变量 `SYLLORA_COURSES_DIR`；桌面注入应用目录，浏览器启动脚本默认仓库根 `.syllora`，测试可使用隔离目录。上传、扫描、阅读、Agent SSE、作答接口不变；大纲仍使用原有 `dailyMinutes/days/deadline/restDays` 参数与校验。

完整说明：[前端接口交接](前端接口对接说明-2026-10-02.md)、[课程目录契约](COURSE_PROJECTS.md)。
