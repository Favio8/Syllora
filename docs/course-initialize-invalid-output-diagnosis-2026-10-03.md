## 结论摘要

截图中的 `INVALID_OUTPUT` 是初始化任务对“未被更具体错误分类覆盖的生成失败”的兜底分类。它说明初始化没有产出可发布的新 revision，但不能单独证明模型返回了非法 JSON，也不能仅凭错误码区分以下原因：

- 模型输出无法通过讲义 schema 或内容约束；
- 概念、示例引用无法匹配对应资料原文；
- 某些 Source 没有被讲义覆盖；
- 资料章节边界解析错误，导致模型批次组成不合理；
- 旧解析缓存或讲义缓存与当前解析规则不一致；
- 缓存内容格式损坏或来自不同资料集合；
- 其他未分类的上游生成失败。

当前离线证据支持的判断是：初始化链路中存在会放大单个异常批次影响的边界问题，且章节识别曾把类似“第1节的准确原文依据足够生成一个概念。”的正文误判为新章节。现已修复章节边界、批次失败隔离、缓存版本和 Point 身份冲突问题，并完成类型检查、定向测试、全量测试以及桌面宿主资源重建。

这些检查没有访问“电路分析基础”的真实课程目录，没有调用真实模型，没有启动桌面应用，也没有操作模拟器。因此目前不能宣称该课程已经成功恢复。

## 截图能证明什么

截图显示课程初始化失败，任务错误码为 `INVALID_OUTPUT`。结合任务错误分类代码，该错误码是未被其他专门错误码识别的生成失败兜底值。

截图不能证明：

- 模型服务是否实际返回了非 JSON 内容；
- 模型返回是否只在某一个概念或某一个批次失败；
- 失败发生在模型调用、schema 校验、引用校验、Source 覆盖校验、缓存读取还是 revision 发布前的其他阶段；
- 失败是否由课程资料本身、模型上下文长度、网络或认证状态引起。

因此，不能把 `INVALID_OUTPUT` 直接等同于“模型输出 JSON 格式错误”。要确定真实课程的具体原因，仍需在不泄露课程资料的前提下查看该次初始化任务的结构化失败原因、批次边界和服务日志。

## 已定位的离线问题

### 1. 编号正文可能被误判为章节

旧的章节识别逻辑对编号开头的行判断过宽。正文行例如：

```text
第1节的准确原文依据足够生成一个概念。
```

可能被当作新的章节标题。这样会改变 Source 的 `section`，并把标题与正文拆开，进而影响：

- 合批边界；
- 讲义模型调用的批次大小；
- 标题与正文的原子单元划分；
- Source 覆盖验证；
- 失败后二分的定位粒度。

### 2. 一个失败父批可能扩大失败范围

如果完整批次最终无法通过内容验证，直接放弃整批会让原本可成功处理的资料一起失败。尤其当批次内含多个章节时，无法区分单个异常小节与其他可用小节。

### 3. 同名概念的身份可能冲突

不同章节可能包含同名概念。若只使用章节和概念名生成未经消歧的 `originKey`，不同知识点可能被误认为同一个 Point，造成静默合并或错误复用旧 Point ID。

### 4. 旧解析缓存可能绕过新的章节边界规则

章节解析规则改变后继续读取旧 `parse-v4` 缓存，会让修复后的扫描器无法接管已有资料，导致同一份材料在不同时间得到不同的 Source 分段。

## 当前代码修复

### 章节识别统一化

文件：`packages/host/chat-service/src/syllora-files.ts`

当前使用统一的 `numberedChapter` 判定，并让扫描入口和正文续段循环共用该判定：

- 保留 Markdown heading；
- 保留中文编号章节，例如“第2节结论”；
- 保留数字编号章节；
- 排除普通数字列表；
- 排除公式、运算符开头的行；
- 排除“第1节的……”这类正文；
- 允许中文无空格章节标题；
- 避免入口判定和正文边界判定不一致。

Source 仍保留稳定的材料 ID、版本、原文偏移、章节、上下文和前后链接信息。

### 内容错误重试与递归二分

文件：`packages/host/chat-service/src/syllora-initialize.ts`

当前流程为：

1. 对讲义生成执行最多 3 次内容重试；
2. 每次重试把上一轮错误压缩为反馈提示；
3. 取消、版本冲突、鉴权、配额、限流、超时和存储类错误直接传播；
4. 内容验证仍失败时，将批次按“标题 + 对应正文”组成原子小节；
5. 按 Source 顺序递归二分；
6. 左右子批在同一顶层 worker 内顺序执行，不提高并发峰值；
7. 成功子批独立缓存；
8. split checkpoint 保存子批 Source ID；
9. 父批不合法时不保存父批缓存，只保留已验证的子批结果；
10. 任何失败都会阻止新 revision 发布，旧 revision 保留。

这样，单个异常小节不会再自动拖垮同一批次中所有可成功的小节，同时仍保持失败结果不会覆盖可用版本。

### `originKey` 消歧与旧 Point 复用

同一基础键重复出现时现在增加稳定序号后缀，例如：

```text
<base-key>
<base-key>#1
<base-key>#2
```

复用顺序为：

1. 精确匹配 `originKey`；
2. 对没有 `originKey` 的 legacy Point，按章节、名称和来源重叠匹配；
3. 每个旧 Point ID 只允许复用一次。

这避免了同名章节或同名概念之间的静默合并，并保持成功重放时 Point 身份稳定。

### 缓存与验证边界

- 解析缓存键从 `parse-v4` 升级为 `parse-v5`，避免旧章节边界缓存继续生效；
- 讲义缓存继续使用 `lecture-v2`，并包含模型标识和 Source 内容结构；
- 读取讲义缓存时先执行 schema 校验，再执行引用和覆盖校验；
- schema 不合法、引用不匹配或存在 foreign Source 的缓存按未命中处理；
- 只有全部资料成功组织并完成最终校验后才写入新 revision。
