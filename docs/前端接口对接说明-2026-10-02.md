# UI 修复后的接口交接

日期：2026-10-02。本次恢复原 UI，继续使用现有 Host，不新增第二套业务 API。以下为前端接线说明，字段完整定义以代码和既有 API 文档为准。

## 传输与状态

工作台请求经过 `apps/web/src/features/workbench/services.ts`：`POST /api/syllora/{action}`，JSON 请求为 `{ "payload": {...} }`，成功返回 `{ "ok": true, "result": ... }`，失败返回 `error.code`、`error.message` 并携带相应 HTTP 状态码。运行时令牌存在时通过 `Authorization: Bearer` 传递，不能塞进预览 URL。Agent/供应商接口由 `apps/web/src/lib/api.ts` 与 `useChatStream` 继续管理。

前端以 `state` 返回的 `SylloraState` 投影主页、课程、看板和统计。课程实体、已发布资料及来源、计划、草案、问题、作答、任务和证据状态继续由后端决定；UI 收起、分区及页面切换不应产生学习证据。

## 入口对应关系

| UI 入口 | 既有接线 | 对接要求 |
| --- | --- | --- |
| 主页/课程/看板 | `state`、既有课程动作与轮询 | 返回实际数据，不以演示统计填充；保留课程 ID、图标、归档状态、时区和修订号。 |
| 更换课程 | 前端选课，复用草稿保存与 Agent 课程注册流程 | 切换前等待草稿保存；冲突/失败时保留未提交内容。 |
| 课程重命名 | `rename`，payload 含课程上下文、`name`、`icon` | 图标使用既有键值；投影层根据类别取颜色，不另存任意颜色字符串。 |
| 归档/删除/移除资料 | `Syllora.tsx` 内既有 `run` 动作 | UI 先显示确认，再执行原动作；真实记录、原文件保留规则按后端实现。 |
| 对话发送/停止/追问 | `WorkbenchChat` → `useChatStream`，`POST /api/chat/stream` | 保留现有请求结构和 SSE 事件处理，不改为同步假回复；会话恢复、工具调用、审批、消息分支、队列继续沿用。移除的模型/教学选择器不意味着移除后端默认配置。 |
| 上传资料 | `pickMaterialFile` → 既有隐藏 file input 导入流程 | 对话/阅读共用入口；上传后刷新实际资料列表，阅读模式不跳变。扫描/初始化、指纹、权限与解析限制沿用。 |
| 练习 | `openPractice` → 既有任务练习/右栏复习 | 不自动产生测试题或“通过”记录；作答、辅助标记及复测状态仍由原动作处理。 |
| 阅读正文 | `readingDocument`，`{courseId, materialId}` | 返回 `id/name/revision/content/sources/source/previewUrl`；前端补充 `courseId`。保留章节/段落来源和正文版本。 |
| AI解释/AI搜索 | `generate`，kind 为 `answer`，附 `reading` | reading 包含 `materialId/revision/selection/sourceIds/mode`，mode 为 `explain` 或 `search`。选区必须属于当前来源，最多 12 个片段。 |
| 阅读回答任务 | `state` 轮询、`cancel` | 返回 `jobId`；成功消息通过 job 的 `resultMessageId` 定位，校验资料修订。取消/切换资料时沿用 AbortSignal 与后端取消，不展示过期回答。结果引用回跳真实来源。 |
| 用户名称/学习时间/外观 | `uiPreferences` | 读取无变更 payload；保存传 `name/theme/dailyMinutes/baseVersion`，返回最新偏好与 `revision`。类型见 `apps/web/src/types/syllora.ts`。 |
| API 配置 | `settings.get/providerCatalog/saveProvider/setCredential/deleteProvider/activateProvider` 等既有 `api` 方法 | 供应商配置与密钥独立保存；保留连接/发现能力和错误反馈。没有虚构服务端未支持的字段。 |
| 用户退出 | 本地退出状态与草稿保存 | 未接入真实账号认证；不能把本地退出当成服务端注销。未来接入账号后在此位置替换真实登出并清理对应会话令牌。 |

## 修订、重试和密钥

- `uiPreferences`、学习设置和草稿保留 `baseVersion` 比较。遇到 `VERSION_CONFLICT` 保留本地输入，显式载入最新值，不偷偷覆盖。
- `logicalRequest` 为变更请求复用 `requestId`，网络失败后查询原任务。后端必须保持既有幂等语义，避免重复生成或扣费。
- 供应商 `saveProvider` 支持现有 `id/name/model/baseUrl/temperature/maxConcurrency/protocol/models/overwrite`；省略的可选字段按现有 merge 语义处理。`setCredential({providerId,apiKey})` 与配置保存独立。不要把密钥写入 UI 偏好、截图、日志或返回的可显示状态。
- 原文件预览仍使用带认证头的 fetch，再创建临时 Blob URL；关闭/资料版本切换释放 URL。

## 唯一新增的桌面桥接

`window.sylloraDesktop.setWindowTheme(theme)` → IPC `syllora:window-theme`，theme 仅允许 `light` 或 `dark`，成功为 `{ok:true}`。非法主题或非当前可信主页面调用被拒绝。此接口只更新原生标题栏按钮外观，不参与后端课程和模型配置。普通浏览器没有此桥接，前端通过可选调用保持兼容。

桌面继续启用 `contextIsolation`、`sandbox`，关闭 `nodeIntegration`；本次未向页面开放 Node 或额外凭据。

## 自动课程目录接口

`POST /api/syllora/createCourse`：`{payload:{requestId:<UUID>,name:<1–60字符>,icon?:<课程图标枚举>,timezone?:<IANA时区>}}`，返回 `{ok:true,result:{id,path,created}}`。`id=requestId`，`path` 由服务端决定；前端只显示课程名称，不提供目录输入。使用 `logicalRequest` 保持网络失败后的请求 ID。重试返回原课程，同 ID 不同参数返回 `REQUEST_CONFLICT`。

`POST /api/syllora/migrateCourse`：新版 UI 仅传 `{payload:{courseId:<旧课程UUID>,requestId:<请求UUID>}}`，由后端分配目标；旧 `path` 参数仅兼容历史客户端。

`initialize` 默认 `acceptPartial:true`，UI 移除开关但依然展示真实失败诊断。完全无文本、文件越界、容量限制、来源版本过期及无来源引用的校验继续生效。

`import`、`scan`、`readingDocument`、Agent SSE、计划与作答接口未变；`state.courses[].folder` 返回新的托管课程目录。大纲表单仅调整排版和短标题，`dailyMinutes/days/deadline/restDays` 的原有校验与含义不变。
