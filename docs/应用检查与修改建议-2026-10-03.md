### B01：笔记保存缺少版本冲突保护

**复现：**两个页面读取同一篇笔记；A 保存新正文后，B 用旧正文编辑并保存。第二次保存成功，最终正文只剩 B 的内容，A 的修改被覆盖。隔离测试已确认 `staleSaveAccepted=true`。

**原因：**`notes/update` 只接收 `noteId/title/content`，没有读取版本或正文摘要的前置条件；写入直接覆盖文件。界面中的离开确认解决不了不同页面之间的覆盖。

- [ ] 给笔记元数据增加稳定递增的 `revision`，读取返回版本，保存要求 `baseVersion`。
- [ ] 版本校验与写入放进同一临界区；冲突返回 `VERSION_CONFLICT`，保留本页草稿，允许查看差异、复制草稿或载入新版本。
- [ ] 正文使用临时文件与原子替换，并为正文、索引元数据的部分写入失败设计恢复策略。

**验收：**两个页面从版本 N 开始编辑，A 保存为 N+1 后，B 的保存必须被拒绝；A 正文不变，B 草稿仍可取回。

定位：[Host 笔记更新](D:/xks/Syllora-main/packages/host/chat-service/src/syllora.ts:771)、[前端更新接口](D:/xks/Syllora-main/apps/web/src/lib/api.ts:597)。证据：[合成并发结果](D:/xks/docs/应用检查-2026-10-03/验证证据/note-concurrency.json)。

### B02：应用目录迁移后课程“消失”

**复现：**在应用 A 目录创建课程，将整个应用目录和 `.syllora` 一起移动到 B；共享注册表保持原样，按 B 下的 `.syllora` 重启服务。结果课程数量为 0，报“课程文件夹已移动或不存在”，而 B 中的原资料实际存在。**这是路径识别失败，本轮没有观察到原文件被删除。**

**原因：**注册表存绝对旧路径；迁移逻辑先读取旧路径，再判断新位置，旧目录不存在时无法利用已搬来的课程目录。当前 UI 又没有重新选择课程目录的入口。

- [ ] 启动时先检查当前 `.syllora/<UUID>`，校验课程身份和快照后重新绑定注册表。
- [ ] 管理目录中的课程采用“课程 UUID + 当前管理根目录”定位，绝对路径保留为兼容信息。
- [ ] 同 UUID 多份目录冲突时明确提示并停止覆盖；保留原件，不能自动新建空课程冒充恢复。

**验收：**同目录升级、整目录搬移、安装目录变更、原目录失踪及重复身份冲突分别测试；搬移后仍能读取原课程和笔记。

定位：[迁移顺序](D:/xks/Syllora-main/packages/host/chat-service/src/syllora-projects.ts:101)、[旧路径校验](D:/xks/Syllora-main/packages/host/chat-service/src/syllora-projects.ts:62)。证据：[目录迁移结果](D:/xks/docs/应用检查-2026-10-03/验证证据/portable-result.json)。

### B03：处理中关闭确认框会留下隐形模态层

**复现：**点击“移除资料”确认，处理未结束时点右上角关闭；接口随后失败。弹窗仍是 `open=true`，但 `opacity=0`、`pointer-events=none`，错误提示和重试按钮不可操作。

**原因：**通用 Modal 先进入关闭动画，确认框的 `onClose` 随后因为 `busy` 拒绝关闭；Modal 的 `closing` 状态没有恢复。

- [ ] 给 Modal 增加 `canClose/closable`，在开始关闭动画之前判断。
- [ ] busy 期间统一禁用关闭按钮、遮罩关闭和 Esc，或者明确设计可取消操作的统一行为。
- [ ] 被拒绝的关闭动作不能改变可见性；接口失败后应保持弹窗可见并允许重试。

**验收：**慢请求中分别点击关闭、按 Esc、点遮罩，再模拟成功和失败；不能出现隐形弹窗或留在背景的模态锁。

定位：[Modal 关闭动画](D:/xks/Syllora-main/apps/web/src/features/workbench/components/Modal.tsx:13)、[确认框 busy 守卫](D:/xks/Syllora-main/apps/web/src/features/workbench/components/ConfirmDialog.tsx:8)。

### B04：阅读选区没有对应的原文映射

**复现：**原文为 `这是 **线性相关** 的解释。`，界面显示“这是 线性相关 的解释。”。选中整句后点 AI解释，报“选区不属于当前正文，请重新选择”。重新打开资料不会解决这个问题。

**原因：**阅读区渲染 Markdown，但前后端校验仅删除空白后进行原始字符串比较；加粗、链接等语法仍保留在源文本里。前端还用全文 `indexOf` 找第一处匹配，同文重复出现时有错配来源的风险。

- [ ] 从选区实际所在 DOM 节点收集 `data-source-id`，不依赖全文第一处同文匹配。
- [ ] 定义统一的可见文本与原文映射，用共享的 Markdown 解析/规范化规则验证选区及字符范围。
- [ ] 保留课程版本、资料归属和来源校验，不通过取消后端验证来绕过错误。

**验收：**普通文本、加粗、链接、列表、跨段落和重复句子均可正确定位；伪造选区及过期版本仍被拒绝。

定位：[前端选区匹配](D:/xks/Syllora-main/apps/web/src/features/workbench/services.ts:46)、[后端选区验证](D:/xks/Syllora-main/packages/host/chat-service/src/syllora-ui.ts:26)。证据：[截图](D:/xks/docs/应用检查-2026-10-03/验证证据/markdown-selection-error.png)。

### B05：快捷键仍操作旧版布局状态

- [ ] 默认保留原生 Tab 顺序；只在确实存在焦点区域且成功找到目标时劫持按键。
- [ ] 把工作台折叠、标签切换回调接入快捷键，或统一状态来源。
- [ ] 右栏新增“图谱”后，重新明确数字快捷键覆盖哪些标签，更新对应帮助。

**验收：**键盘可遍历输入框、发送、上传、练习和侧栏；Ctrl+B 与点击收起效果一致；数字快捷键切换真实可见标签。

定位：[Tab 劫持](D:/xks/Syllora-main/apps/web/src/hooks/useKeyboardShortcuts.ts:144)、[旧看板状态](D:/xks/Syllora-main/apps/web/src/hooks/useKeyboardShortcuts.ts:87)、[当前工作台](D:/xks/Syllora-main/apps/web/src/components/Syllora.tsx)。

- [ ] 连续失败时适当退避，恢复时显示一次明确状态；不要清掉草稿冲突等仍需处理的提示。

**验收：**失败→恢复后连接提示消失，业务错误仍保留；持续断开不触发重复弹窗。

## 3. 需要复核的对接风险

### R01：新版 Agent 对话可能没有计入主页学习统计（建议 P2）

**源码证据：**主页读取 Syllora 的 `activity`。现有 `recordActivity` 调用记录任务完成与旧 `generate(answer)` 路径；新版对话框走 `/api/chat/stream`，检查到的这条路径没有对应的 `recordActivity` 连接。

因此，用户可能已经进行了多次 Agent 对话，主页互动次数和热力图却不增加。**本轮没有使用真实模型完成付费对话，因此这项记录为对接风险，不作为端到端已确认问题。**

- [ ] 用一次成功的实际 Agent 会话核对 activity，明确“互动次数”按成功轮次、请求还是消息计数。
- [ ] 如确实缺失，以稳定 `turnId` 在服务端追加去重事件；重试与回放不能重复计数。
- [ ] 验证阅读、Agent 对话、任务完成三条路径，并继续区分建议时长与实际计时。

定位：[统计投影](D:/xks/Syllora-main/apps/web/src/features/workbench/projection.ts)、[现有活动记录](D:/xks/Syllora-main/packages/host/chat-service/src/syllora.ts:604)、[Agent 对话入口](D:/xks/Syllora-main/apps/web/src/components/chat/AgentChat.tsx)。
